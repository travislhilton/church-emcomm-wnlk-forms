More Than One EOC

Satellite → Stake Center → Area: One Message Center, Three Levels

Same software at every EOC. Each one names itself, its parent, and the wards it covers — then rolls its records up without anyone re-keying them.

Who reports to whom

How a roll-up moves — same PACE ladder

P/A

Setup tab → Export Roll-up JSON ("only new" ticked) → attach to an email to the parent EOC's drop email. The parent's Drop Folder merges it in 10 s, zero-touch.

C

Same file attached to a Winlink message (VARA FM, or HF) to the parent's Winlink address — about 1 KB per record. The parent's Winlink watcher merges it.

E

USB drive with the printed SITREP by runner → Drop Folder or Import Roll-up JSON (merge).

Nothing is counted twice

A merge skips any record already on file — by id, Winlink Message-ID, or form content — and keeps the parent's own status and notes. The same Disaster Report can arrive by Winlink forward and in a roll-up and appear once.

Volunteers change nothing

Each ward is assigned to one EOC on the stake sheet (§6d). Its Team Leader card carries that EOC's drop email, Winlink address and net. The SITREP shows Section H: Reporting EOCs, so the Stake sees which satellite — and the Area which stake — has gone quiet.

Open a Satellite EOC when wards cannot reach the Stake Center: roads cut, river between, Stake Center dark, or one team swamped

This is the answer to "what if the Stake Center is not reachable, or one part of the stake is cut off?" The same installer choice [3] and the same Message Center run at a ward building as a Satellite EOC, at the Stake Center, and at a Council / Area EOC if the council or welfare region opens one; otherwise the Stake EOC sends straight to the two lines above it, the Area Seventy's council and the welfare line. The only configuration is the Setup tab: level, name, wards covered, and the parent EOC's drop email and Winlink address. The level changes the vocabulary — wards at a Satellite or Stake EOC, stakes at a Council / Area EOC — and the Disaster Report has an optional Ward field for it. Roll-up is one JSON file that rides the same PACE ladder as the SITREP: email attachment at Primary and Alternate, Winlink attachment at Contingency, USB at Emergency. The parent never has to click anything on the first two; the Drop Folder and the Winlink watcher recognise a roll-up and merge it. Dedupe is by id, Winlink Message-ID and a content hash, so forwarding originals and sending a roll-up never double-counts. Import Handoff is a different button: it replaces everything and is only for shift change.
